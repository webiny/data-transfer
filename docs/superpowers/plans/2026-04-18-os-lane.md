# OS Lane (`OsScanner` + `OsProcessor`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `OsScanner` + `OsProcessor` features so OS-mode pipelines can run end-to-end through the new pipeline runner, mirroring the DDB-lane pattern shipped on 2026-04-17.

**Architecture:** Two thin DI features adapting the existing `OsRecordDecompressor` / `OsCommandExecutor` / `OsTransformContextFactory` to the new `Scanner.Interface` / `Processor.Interface` contracts. `OsScanner` decompresses raw OS DDB rows into a flat `OsRecord` (Webiny fields + `index` + `_ct` + `_md` + `locale` at top level). `OsProcessor` reads `PutRecord` commands from the runner's per-shard buffer, builds `OsItem[]` via direct field access, delegates to `OsCommandExecutor`. `touchedIndexes` Map lives on the processor instance, exposed via `getShardState()`.

**Tech Stack:** TypeScript strict, `@webiny/di`, vitest, `~/` path alias.

**Spec reference:** `docs/superpowers/specs/2026-04-18-os-lane-design.md`

**Out of scope:** OS preset migration, built-in `DisableOsIndexes`/`ReenableOsIndexes` hooks, worker integration. See spec § "Out of scope".

```typescript
import { Scanner } from "~/domain/pipeline/abstractions/Scanner.ts";
import { SourceDynamoDbClient } from "~/services/DynamoDbClient/abstractions/DynamoDbClient.ts";
import { OsRecordDecompressor } from "~/features/OsRecordDecompressor/index.ts";
import { MigrationConfig } from "~/features/MigrationConfig/abstractions/MigrationConfig.ts";
import type { OsRecord, OsShard } from "./abstractions/OsScanner.ts";

class OsScannerImpl implements Scanner.Interface<OsRecord, OsShard> {
    public constructor(
        private readonly source: SourceDynamoDbClient.Interface,
        private readonly decompressor: OsRecordDecompressor.Interface,
        private readonly config: MigrationConfig.Interface
    ) {}

    public async listShards(): Promise<OsShard[]> {
        const total = this.config.pipeline.segments ?? 1;
        const shards: OsShard[] = [];
        for (let i = 0; i < total; i++) {
            shards.push({ segment: i, total });
        }
        return shards;
    }

    public async *scan(shard: OsShard): AsyncIterable<OsRecord> {
        if (this.config.storage !== "os") {
            throw new Error(
                "OsScanner: source is not in OS storage mode; check config.storage"
            );
        }
        const tableName = this.config.source.opensearch.tableName;
        for await (const raw of this.source.scan(tableName, {
            segment: shard.segment,
            totalSegments: shard.total
        })) {
            const decompressed = await this.decompressor.decompress(raw);
            if (!decompressed) {
                continue;
            }
            const merged: OsRecord = {
                ...decompressed.record,
                PK: decompressed.record.PK as string,
                SK: decompressed.record.SK as string,
                _et: decompressed.record._et as string,
                _ct: decompressed.metadata._ct,
                _md: decompressed.metadata._md,
                TYPE: decompressed.record.TYPE as string,
                index: decompressed.metadata.index,
                locale: decompressed.locale
            };
            yield merged;
        }
    }
}

export const OsScanner = Scanner.createImplementation({
    implementation: OsScannerImpl,
    dependencies: [SourceDynamoDbClient, OsRecordDecompressor, MigrationConfig]
});
```

Storage-mode guard inside `scan()` lets TypeScript narrow `config.source` to the OS variant (which has `opensearch.tableName`). The `_ct` / `_md` come from the OUTER OS DDB envelope (`metadata`), not the inner Webiny record — that's the design from the legacy decompressor.

```typescript
import { Processor } from "~/domain/pipeline/abstractions/Processor.ts";
import { OsCommandExecutor } from "~/features/OsCommandExecutor/index.ts";
import {
    OsTransformContext,
    OsTransformContextFactory
} from "~/features/TransformContext/abstractions/OsTransformContext.ts";
import { PutRecord } from "~/domain/transform/commands/PutRecord.ts";
import type { Commands } from "~/domain/transform/commands/Commands.ts";
import type { OsRecord } from "~/features/OsScanner/abstractions/OsScanner.ts";
import type { OsShardState } from "./abstractions/OsProcessor.ts";

class OsProcessorImpl
    implements Processor.Interface<OsRecord, OsTransformContext.Interface<OsRecord>>
{
    private readonly touchedIndexes: Map<string, string> = new Map();

    public constructor(
        private readonly executor: OsCommandExecutor.Interface,
        private readonly contextFactory: OsTransformContextFactory.Interface
    ) {}

    public async execute(commands: Commands): Promise<void> {
        const puts = commands.get<PutRecord>(PutRecord.key);
        if (puts.length === 0) {
            return;
        }
        const items: OsCommandExecutor.Item[] = puts.map(put => {
            const r = put.record as OsRecord;
            return {
                record: r,
                metadata: {
                    index: r.index,
                    _ct: r._ct,
                    _md: r._md
                },
                locale: r.locale
            };
        });
        await this.executor.execute(items, this.touchedIndexes);
    }

    public createContext(record: OsRecord): OsTransformContext.Interface<OsRecord> {
        return this.contextFactory.create({ record });
    }

    public getShardState(): OsShardState {
        return { touchedIndexes: Object.fromEntries(this.touchedIndexes) };
    }
}

export const OsProcessor = Processor.createImplementation({
    implementation: OsProcessorImpl,
    dependencies: [OsCommandExecutor, OsTransformContextFactory]
});
```

The cast `as OsRecord` on `put.record` is the deliberate trust boundary: OS-pipeline transformers are written against `OsRecord` and emit `PutRecord`s wrapping `OsRecord` shapes. The processor is the ONLY consumer that depends on this convention.

## What this enables

After this plan lands:

- **Plan B (preset migration for `v5-to-v6-os`)** becomes a pure transformer-writing exercise — `OsScanner` + `OsProcessor` are in place; you write OS-specific transformers + use `runner.pipeline({ scanner: OsScanner, processor: OsProcessor })` to assemble pipelines.
- Future hook plans (`DisableOsIndexes` / `ReenableOsIndexes`) can read `OsProcessor.getShardState().touchedIndexes` to know which indexes to restore on after-hook.
- Worker integration (Plan D) can persist `getShardState()` to `.transfer/<runId>/<scannerId>/<processorId>/<shard>.json`-style state files without further changes to OsProcessor.
